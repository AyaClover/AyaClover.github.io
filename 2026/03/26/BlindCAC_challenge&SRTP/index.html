From a BlindCAC Model to SRTP Project

Created2026-03-26|Updated2026-09-27|research
|Post Views:

Part 1: Overview

The BlindCAC repository serves as the baseline for the NTIRE 2026 challenge, to perform lens aberration correction in a blind manner. The innovative point is that during inference, the model receives only the degraded image without lens parameters. Aiming to begin researching under the guidance of Professor Wang and doctoral students Jiang and Qian, I took a part in this challenge as a member of the team zjgcxxz.

Key tasks included according to the organizers:

  • Environment setup (Python 3.10, PyTorch 1.12.1, CUDA 11.3)
  • Data preparation: paired blurred (ab) and sharp (gt) images, along with lens PSF maps, given by the organizers selected from DIV2K dataset online.
  • Baseline selection: PSF‑guided SwinUnet (primary) and SwinIR
  • Model training on the paired dataset
  • Testing on validation data
  • Inference on unpaired images (no ground truth)

Model Structure

This baseline model contains Swin_Transformer and U_net. Transformer is excellent in the correlation between pixels at a distance, and Unet ensures a highly efficient feature extraction.

Supplementary Practice
Prior to the main work, some preliminary knowledge was acquired. After some exploration and learning from online tutorials, I followed the commands provided online, the environment was set up smoothly. Although there was initial concern that a Linux system might be required, the setup proved feasible on Windows as well.

Downloading the dataset required patience due to slow speeds; accessing the website demanded a VPN, which conflicted with download speed.

Part 2: Training Configuration

The PSF‑guided SwinUnet was chosen as the starting point. Configuration paths were set in train_PSFguided_SwinUnet_gtpsfmap.yml. A key point was keeping validation data separate from training data: the validation set MixLib_demotest was used to monitor generalisation, avoiding overfitting.

Model Size

The model size was estimated based on known architectures:

  • SwinIR (a core component) ranges from 11M to 44M parameters
  • The PSF‑guided SwinUnet adds PSF estimation branches, leading to an estimated 25M–50M parameters

This scale requires GPU resources.

Supplementary Practice
The training phase posed the greatest difficulties. Initially, the process stalled at the first loop. Investigation suggested an escape‑character issue in the paths generated from the CSV file; replacing all single backslashes with double backslashes resolved the problem.

Consequently, efforts were directed toward model lightweighting—reducing channels and parameters to decrease forward and backward computation time. During this process, timing test functions were added to various modules and later removed. Ultimately, the training began. This process also provided an opportunity to understand the roles of various parameters and modules.

Part 3: Monitoring Training

Training logs reported metrics every 100 iterations: l_pix, l_abd, l_percep, and the learning rate. TensorBoard was used to visualise trends.

The SCALARS panel showed during the training period:

  • A downward trend across all losses, indicating convergence
  • Occasional spikes (e.g., l_percep near 0.49 at iter 69,800), which were transient and typical of batch variations
  • A smooth learning rate decay from 7.47e-5 to 7.30e-5

Exporting the curves to CSV allowed further analysis. The visual feedback confirmed that training was progressing as expected.

Part 4: Model Overview

Architecture

  • Generator (SwinUnet_psfprediction_cacstage): A Swin Transformer‑based U‑Net with a codebook for discrete feature representation. It outputs both the restored image and a predicted PSF map.
  • Discriminator (UNetDiscriminatorSN): Used for adversarial training (optional; currently disabled in config).

Training

  • Dataset: Paired blurred (lq), sharp (gt), and PSF maps (abd) loaded via CSV.
  • Losses (weights in parentheses):
    • Pixel L1 loss (1.0) between output and gt.
    • PSF prediction L1 loss (1.0) between predicted and true PSF.
    • Perceptual LPIPS loss (1.0) using pretrained AlexNet.
    • GAN loss (0.0) – currently off.
  • Optimizer: Adam for G (lr=1e-4) and D (lr=4e-4).
  • Scheduler: Periodic cosine annealing: total 400k iters.In the first cycle (0–200k), the learning rate gradually decays from 1e-4 to 1e-6. It reaches the minimum at 200k steps, and then enters the second half-cycle, where the learning rate gradually rises back from 1e-6 to 1e-4.
  • Mixed precision: Enabled (fp16: true).

Key Code

  • psfconstraint_model.py: Implements PSFprediction_guided_CACModel with optimize_parameters (forward, loss computation, backward) and nondist_validation (inference + metric calculation).
  • train.py: Orchestrates data loading, model building, training loop, checkpointing (auto‑resume via training_states), and periodic validation.
  • test.py: Loads a model and runs nondist_validation on test datasets; supports paired or single‑image datasets.

Testing

  • Paired test: computes PSNR, SSIM, LPIPS.
  • Unpaired test (no ground truth): switch dataset to SingleImageDataset and remove metrics.

Checkpoint & Resume

  • Checkpoints saved every 40k iterations (.pth for weights, .state for optimizer/scheduler).
  • Auto‑resume loads the latest .state file; no extra command needed.

Part 5: Testing on the Validation Set

Testing began on the validation set (MixLib_demotest), which includes ground truth.

Results on the Validation Set

After processing 216 images, the average metrics were:

  • PSNR: 23.86
  • SSIM: 0.772
  • LPIPS: 0.1957

These values reflect a reasonable baseline, though there is room for improvement, particularly in PSNR.

Part 6: Adapting to Unpaired Test Images

Supplementary Practice
Inference proceeded relatively smoothly. The PSNR result is 22.4 for unpaired images.

Because my model was focused on the model training speed, I appropriately reduced the number of layers, which leaded to a result that the metrics were not as good as the original model. And the visual quality of the results did not match the level achieved by other participants.After discussion, our team selected my teammate’s model for next step interference.

Configuration Changes

In test_PSFguided_SwinUnet.yml:

  • Dataset type was switched from PairedImageDataset to SingleImageDataset
  • dataroot_lq was set to the folder containing unpaired images
  • The metrics section was removed entirely, as ground truth was unavailable

Execution and Output

Running the same test.py script performed inference without metrics. The corrected images were saved in the experiment’s results folder, ready for visual inspection.

Key Takeaways

This experience reinforced the importance of practical workflow considerations alongside model development. Next steps include experimenting with perceptual loss and exploring lighter architectures for faster inference.

Future Work
Based on this challenge, it was observed that images generated by different teams with varying scores often showed little visual difference; in some cases, images with higher scores even appeared worse to the naked eye. Therefore, a subsequent task will be to investigate the image metrics themselves.
